# Feature: Spot Comments & Community Activity Feed

**Status:** ready (updated 2026-09-22 per grilling session — see `docs/adr/0001-activity-feed-community-home.md` and `docs/superpowers/plans/2026-09-17-comments-frontend.md`)
**Priority:** high
**Affects:** New feature: `src/features/comments`; Modified pages: `src/app/page.tsx`, spot detail component `src/features/spots/components/SpotDetail/index.tsx`

## Problem Statement

Skateboarding spots need community discussion. Users should be able to leave comments on spots, add heart reactions, and edit/delete their own comments. The home page shows a community-wide activity feed of recent comments across all spots, keeping the platform social and alive.

The backend implementation is on branch `feature/spot-comments-reactions` (PR #87, ready — see `docs/superpowers/specs/2026-09-17-comments.md` in the Strapi repo). This spec covers the frontend UI layer only.

## UI / UX Description

### Spot Detail Page (`/spots/[id]`) — Comments Section

**Location:** The right-hand column of the "Map + Comments" grid in `SpotDetail`, replacing the current disabled placeholder.

**Components:**

- **Comments header** — Shows comment count and "Sort by: Newest/Oldest" selector (client-side sort)
- **Comment list** — Displays all comments for the spot (fetched all at once)
- **Individual comment card** — Shows:
  - Author avatar + name + relative timestamp (e.g., "há 2 horas")
  - "Editado" hint when `updatedAt !== createdAt`
  - Comment text
  - Attached images (if any) displayed as a grid below text
  - Heart reaction count + current user's heart status (filled or outline)
  - "Edit" and "Delete" buttons (visible only to the comment author)
- **Comment form** (visible to authenticated users only) — Appears above the comment list:
  - Textarea for comment text (placeholder: "Share your thoughts about this spot...")
  - "Add images" button to upload 1-5 images
  - Submit button ("Post Comment" / "Update Comment")
  - Character count indicator (e.g., "250 / 500")
- **Comment anchor** — Supports `#comment-<id>` deep links: scrolls into view and softly highlights the target comment

**Interactions:**

- Unauthenticated users see the comment count and list but cannot comment or react
- Clicking the heart icon toggles the reaction **optimistically** (updates immediately, reverts on failure)
- Clicking "Edit" on own comment opens an inline editor (text + images)
- Clicking "Delete" on own comment shows a confirmation modal before deletion
- After submitting a new comment, the textarea clears and the new comment appears at the top of the list

### Home Page (`/`) — Community Activity Feed

**Location:** New section on the home page below `StoriesHome` / `SkatistasHome`.

**Title:** "Atividades recentes"

**Components:**

- **RecentCommentsFeed** — client component mirroring the `StoriesHome` hook pattern (Q12)
- **Each activity card shows:**
  - Author avatar + name
  - Spot name (clickable link to `/spots/<id>#comment-<id>`)
  - Comment text (truncated, expandable)
  - Reaction count
  - Relative timestamp (e.g., "há 3 dias")
- **Read-only** — no react, edit, or delete controls on the feed (interactions happen on the spot page)
- **"Load more"** pagination button — initially 10 comments, appends pages until `total` reached
- Handle loading/error/empty states

## Data Requirements

All endpoint shapes are defined in the backend spec: `specs/comments.md` (Strapi repo, `feature/spot-comments-reactions` branch) — `## API Contract` section.

Key endpoints consumed:

| Endpoint                                                                       | Auth                | Used on                                                                        |
| ------------------------------------------------------------------------------ | ------------------- | ------------------------------------------------------------------------------ |
| `GET /api/comments?filters[spot][id][$eq]=<spotId>&sort=-createdAt`            | Public              | Spot detail comments list (no populate params — server fixed populate applies) |
| `GET /api/comments?sort=-createdAt&pagination[page]=1&pagination[pageSize]=10` | Public              | Home page community activity feed                                              |
| `POST /api/comments`                                                           | Bearer JWT          | Comment form submit                                                            |
| `PUT /api/comments/:id`                                                        | Bearer JWT + author | Edit comment                                                                   |
| `DELETE /api/comments/:id`                                                     | Bearer JWT + author | Delete comment                                                                 |
| `POST /api/reactions/upsert` body `{ "data": { comment, type: "heart" } }`     | Bearer JWT          | Toggle heart reaction (201 created / 204 deleted)                              |
| `POST /api/upload`                                                             | Bearer JWT          | Upload comment images                                                          |

**Backend contract notes** (verified against Strapi code):

- Client `populate` params are always overridden by the controller's fixed `POPULATE`. The controller must additionally populate `spot: { fields: ["id", "name"] }` and `author.avatar` (`url` + `formats.thumbnail.url`) for the frontend feed to render spot links and avatars (planned backend change on PR #87).
- List meta is `{ pagination: { total } }` only. Pagination params are honored server-side; the feed derives its "load more" from `total` vs loaded count.
- Upsert reads `ctx.request.body.data` — body must be `{ data: { comment, type } }`, not flat.

- [x] "editado" appears when `updatedAt !== createdAt`
- [x] Heart reaction count is displayed per comment
- [x] Current user's heart reaction status is visually indicated (filled if reacted, outline if not)
- [x] Unauthenticated users see comments but cannot comment or react
- [x] "Edit" and "Delete" buttons are visible only to the comment author
- [x] Clicking heart toggles reaction **optimistically** (updates immediately via `POST /api/reactions/upsert`, reverts on failure)

## Out of Scope

- Comment threading/nesting (flat structure only)
- Advanced comment moderation workflows and admin notifications
- Flagging / reporting UI (deferred — see Q4)
- Comment mentions or tags (@-mentions)
- Comment search/filter by text
- Signal/time-based privacy of the feed
- Real-time comment updates (no WebSocket)
- Reaction types beyond heart reactions
- The dashboard's "Atividades recentes" placeholder (left untouched, Q11)
